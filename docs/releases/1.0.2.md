# Nadiano 1.0.2

Nadiano 1.0.2 completes the remaining software-enforceable 1.0 roadmap scope and strengthens the stable release gates.

## Learning content

- 110 guided German/Indonesian lessons remain available from F0 through B2 with selected E1 foundations;
- the generated catalogue now contains 120 rhythm/technique exercises and 120 reading configurations;
- 60 deterministic ear-training tasks cover direction, short-pattern imitation and tonal memory;
- 24 original Nadiano mini-pieces are included as generated Nadiano compositions;
- 12 public-domain compositions are represented by independently authored simplified Nadiano study editions;
- the E1 stage check remains the final beginner assessment;
- roadmap quantities are checked by the normal content validator and therefore block a stable release when underfilled.

## Practice and private library

- release repertoire is converted to MusicXML and expected events through the same notation, MIDI and scoring path as other practice material;
- sight-reading is available with a 15-second preparation view before the normal count-in and scored attempt;
- private MusicXML/MXL items can be exported as a `.nadiano.zip` package containing the original file, normalized MusicXML and versioned metadata;
- private package responses remain profile-scoped and `no-store`.

## Release hardening

- the stable workflow enforces frontend bundle-size budgets;
- release assets include a deterministic third-party NuGet/npm license report;
- the release rehearsal now verifies Beta-to-stable upgrade, cold restore into a clean volume and rollback by restoring the pre-upgrade backup with the Beta image;
- the existing .NET, frontend, content, Chromium, secret, dependency and container vulnerability gates remain required;
- immutable version and commit-SHA image tags are published only after the release gates pass.

## Manual acceptance

Real browser permission state and household hardware cannot be reproduced by GitHub Actions. Current Chrome/Edge first-run checks, production HTTPS PWA installation/reconnect, manual keyboard accessibility review and modest-hardware profiling remain explicit manual acceptance records rather than fabricated automated passes.
